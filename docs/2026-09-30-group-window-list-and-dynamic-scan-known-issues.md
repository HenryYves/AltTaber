## 一、验收状态（最重要的一条）

| 功能 | 验收状态 |
|---|---|
| Alt+` 弹出组列表（入口 A） | **用户实测验收通过**（清单 A 组 8 条） |

| **切换期间动态扫描**（`watch_new_windows` / `auto_select_new`） | **未验收** —— 见下 |

**动态扫描为什么未验收**：用户明确表示用不上这个需求，主动决定不做验收（2026-09-30）。
**不是失败、不是阻塞、不是忘了**。代码保留，两个开关**默认关闭**，日常使用不受影响。

**但这意味着**：`WindowWatcher` 的 300ms 轮询、新窗口入列、自动选中、以及那轮几何刷新，
**只有静态复审与离屏探针证据，没有任何人在真实桌面上跑过**。将来想启用它的人，
请把它当作一个**未验收的新功能**，而不是一个已经用过的功能。

**其中风险最高的一项是**（复审已点名、且任何人都不可能在离屏环境复现）：
动态增删后调用 `setGeometry()` 去调整一个**已经可见的无边框半透明窗口**。
这是 Windows 窗口管理器行为，原作者在 `src/widget.cpp:464-467` 附近的注释里
**记录过他当年就因图标数量变化而调整这个窗口时遇到过麻烦**。若启用动态扫描后
出现"新程序不显示 / 面板尺寸不对 / 闪烁"，**先查这里**，不要怀疑监听逻辑。

## 二、代码里的一处**假注释**（最该顺手清掉的一条）

`src/widget.cpp:763` 写着：`旧注释的"滚轮冒泡"说法不成立`。

**这句话是假的。** Task 9 的探针是走**真实平台投递路径**测的（`QTest::wheelEvent` →
`QWindowSystemInterface`，不是手工模拟再投递），实测到真实滚轮在**一个方向上确实会冒泡到
`lw` 对象上的过滤器**（`angle=+120 → lw filter wheel=1`，`angle=-120 → lw filter wheel=0`）。

讽刺的是：**这句假话是一次"修注释准确性"的改动引入的**——它在纠正旧说法时，把另一个
被实测过的机制给断言掉了。而且它**恰好否定了最终复审另一条 finding 所依赖的机制**
（那条 finding 讲的"既有滚轮方向不对称"就是由这个冒泡造成的）。

修法：删掉那半句，或改成只限定组列表（`真实滚轮在组列表上永远不会到达对象那一半，
因为视口分支会消费掉它`）。**一行注释，零运行时影响。**

同一条注释还有个更细的点：它引的 `:151`（`postEvent(lw, …)`）是 **AppMode 列表**的路径，
组列表**没有**这种投递；而且真实点击不会冒泡到对象（探针 A4：`lw filter mouse=0`）。
所以 `onGroupList` 里 `|| watched == groupList_->widget()` 那一半**未被证实**，
可能是防御性死代码。无害，但别把它当成"必要"。

## 三、**预先存在**、本支线只是暴露了它的问题

### 3.1 AppMode 滚轮方向不对称（建议单独一轮修）

`src/widget.cpp:782` 的 `watched == lw && QEvent::Wheel` 分支**只在一个方向触发**：
`updateListWidth()` 算出的宽度让列表仍留了 **约 3px** 的横向可滚范围，
当视图能滚时它会消费掉滚轮、事件不再冒泡。

**这不是本支线引入的**：基线 `a665f50:src/widget.cpp` 里公式（`:299-301`）与条件（`:423`）
逐字相同，本支线只是把它搬进了 `updateListWidth()`。

当时不修的理由：改那个条件要碰文件里最娇贵的**任务栏缩略图偷鸡逻辑**，
而那条路径**谁都没法离屏复现**。证据齐了，值得单独一轮。

### 3.2 其它预先存在的小项

- `insertAppItem` 不查 `winActiveOrder_`：所以一个"有陈旧活跃记录但列表项已不在"的进程会被
  追加到末尾而不是按最近使用排序；同一 tick 内多个新进程会按 `added` 的倒序落位。**下次弹窗自愈**。
- `GroupWindowList::clear()` 不重算固定宽度：两个调用点都是销毁路径，中间不会显示列表，**无害**。
- `moveSelection(delta)` 从"无选中"（`currentRow() == -1`）进入时不对称
  （n≥3 时 `delta=-1` 落到 n-2 行）。实际路径都会先设初始行，够不到。
- `preferredSize()` 忽略滚动条宽度；且 `rows*RowHeight + PaddingV` 会把 16px 垂直内边距
  **全放在面板底部**（视觉小瑕疵，未经肉眼确认）。

## 四、测试与依据上的洞

- **那 18 条断言没有人在跑。** `tests/window_diff_tracker_test.cpp` 建了可执行文件，
  但没有 `enable_testing()` / `add_test`，也没有 CI —— 只有人手敲路径才会跑。
  且它按构造只覆盖 `WindowDiffTracker`，**完全覆盖不到任何 GUI 代码**。
- `tests/window_diff_tracker_test.cpp:92`（`seed() records the windows`）**无法单独变红**
  （要 `seed` 与 `update` 同时坏）；`reset()` 与 `removed` 的排序路径不在那 4 条变异集里。
  —— 答得出"改错成什么样它会红"，只是当前变异集没覆盖。
- `tests/window_diff_tracker_test.cpp:22` 用 `intptr_t` 但没有 `<cstdint>`，靠 `<Windows.h>` 传递引入。
- **300ms 间隔与"每 tick 约 2ms"的依据从未被精确测量。** 唯一一次测到的**有效周期是约 680ms**
  （Task 2 期间测的，当时构建里还留着一条逐 tick 的日志行；成因未查明、之后没复测）。
  设计文档里"占空比 <1%"的论证建立在那个 2ms 之上，**可能偏乐观**。
- `src/utils/Util.cpp:338` 的 `#ignore elevated:` 仍对每个被跳过的提权窗口打一条日志
  （已去掉其中跨进程的 `getWindowTitle()` 调用，但轮询期间仍是 3.3Hz × N）。
